# 大塚综合数字孪生平台

面向工业园区能源管理场景的 React + Three.js 可视化大屏。中心区域使用 Blender 生成的厂区 GLB，支持建筑选择、整栋楼层爆炸拆分、环厂交通、停车场和闸门车辆通行动画。

## 功能

- 水、电、蒸汽等能源指标和趋势图表
- 可旋转、缩放的半写实工业园区
- 12 栋可点击建筑及楼层业务信息
- 点击建筑后所有楼层同步爆炸展开
- 建筑外壳消隐、楼层发光轮廓和能量轴效果
- 四周环形道路、道路车辆、停车场和门卫闸机
- 车辆识别、等待开杆、通行、清场落杆的同步闸门周期
- 原料配送、设备维保和消防巡逻三条 Blender 路线及动态车辆
- 交通演示启停控制；暂停后运营车辆返回确定性起点
- 日间 / 傍晚照明模式及道路、立面灯具联动
- 默认日间 + Unity 风格的 Web 渲染，可切换驾驶舱风格并实时调整阳光、环境光与 PBR 反射
- 厂区引导漫游、站点切换、暂停/继续和退出控制
- 静态网格实例化、分级细节和指针拾取调度，改善局域网设备的加载与拖拽性能
- 响应式 16:9 大屏及减少动态效果适配

## 当前版本界面

- 一级驾驶舱采用左右窄数据栏与扩大后的中央厂区视口；水、电侧栏底部对齐，蒸汽模块压缩高度后与两侧共用同一底线。
- 水、电、蒸汽一级模块提供趋势、运行质量、分区/设备状态和详情入口；底部能源总量栏采用紧凑高度，避免与上方模块产生过大空隙。
- 二级能源页面保持中央厂区模型可见，左右分析栏与一级页面共用中心宽度；顶部页签可切换总览、分区、设备/管网和告警数据。
- 二级页面底部使用四个 ECharts 图表展示分区排行、告警闭环、设备健康和七日预测；“返回首页”位于左侧资源详情标题栏，支持点击或 `Esc` 返回。
- “专注厂区”会以动画隐藏驾驶舱数据层，只保留厂区模型与场景控制，退出后恢复原布局。

## 技术栈

- React 18
- Three.js
- ECharts
- Vite 5
- Blender 5.2 LTS / glTF 2.0
- Node.js 内置测试运行器

## 本地启动

```bash
npm install
npm run dev -- --host 0.0.0.0 --port 5180
```

打开 [http://localhost:5180/](http://localhost:5180/)。

## 页面入口

- `/`：完整 Web 驾驶舱，包含 Blender 厂区模型、能源总览、二级分析、楼层爆炸和园区交互。
- `/unity-dashboard`：Unity 嵌入专用驾驶舱，只渲染顶部、水、电、蒸汽和底部数据板块；中央厂区区域保持透明，且不会挂载 Three.js 场景或重复加载 Web GLB。

本地调试可直接打开 [http://localhost:5180/unity-dashboard](http://localhost:5180/unity-dashboard)。普通浏览器会用页面或窗口底色合成透明区域，因此中央区域可能看起来是白色；嵌入 Unity 时需要让 WebView/浏览器纹理启用透明背景和 Alpha 合成，Unity 相机画面才能从中间区域透出。

生产构建：

```bash
npm run build
```

## 场景交互

- 拖拽：旋转园区视角
- 滚轮：缩放视角
- 点击建筑：打开建筑信息并同步展开全部楼层
- 点击楼层：镜头进入该层三面剖切空间，显示功能分区、家具/设备和行走人员
- 合拢楼层：恢复建筑楼层结构
- 日间 / 傍晚：切换园区环境曝光、雾、主光及运行灯具
- 交通运行中 / 已暂停：启动或暂停内部配送、维保和消防巡逻车辆
- 首页能源脉冲：厂区模型上沿常驻展示实时水流量、电负荷、蒸汽流量、最大需量、在线仪表和待处理告警六路信号
- 水资源详情：点击左侧水资源面板的“查看详情”或底部“总用水量”，打开水资源二级分析工作区
- 电力资源详情：点击右侧电力面板的“查看详情”或底部“总用电量”，打开电力资源二级分析工作区
- 蒸汽资源详情：点击下方蒸汽面板的“查看详情”或底部“总用汽量”，打开蒸汽资源二级分析工作区
- 二级工作区：左侧持续显示趋势与分项，右侧持续显示设备状态与告警，底部显示分区排行、告警闭环、设备健康和七日预测四个 ECharts 图表；页签只改变关注重点，不清空其他运行上下文
- 二级工作区可通过“水 / 电 / 汽”快速切换能源类型；点击左侧资源详情标题栏中的“返回首页”或按 `Esc` 关闭
- 复位视角：返回前左方向的园区总览

水、电、蒸汽二级工作区均覆盖在驾驶舱数据层之上，不重新加载页面。打开后原有概览面板平滑退场，趋势、分项、设备、告警与运行图表分别进入左、右、下三块环绕区域，中央 Blender 厂区模型保持共享中心宽度和原相机；同一时间只显示一个能源详情，可在二级工作区内直接切换能源类型。

## Blender 模型

厂区模型采用 Blender 参数化建模并导出为 glTF 2.0。当前模型不是单纯的白盒占位：在保留参考图总体布局的基础上，厂区占地扩展为原来的约两倍，建筑体量同步增强，并补充建筑墙板分缝、基座、檐口、窗带、装卸门、屋顶设备及管廊等工业建筑构造。综合管理中心采用通高玻璃中庭、石材翼楼、四柱门廊和金属线脚形成园区主楼；前区设置放大篮球场及带球网、标线和围网的网球场。主要建筑按楼层拆分，并在楼层内部布置生产设备、检修设施、办公家具和行走人员，供 Web 端爆炸分层及内部视角使用。

建筑外观按功能进一步区分：综合管理中心增加企业标识和覆盖落客前场的门廊体系；主生产车间使用屋面高窗监控体、侧向附属机房和百叶设备墙形成高低跨轮廓；原料仓库采用三工位连续装卸月台，成品仓库采用双工位装卸节奏；东区工艺车间显露管线入口、通风百叶和屋面洗涤设备；公用工程站以大面积百叶、屋面设备基座和排气筒表达动力设施属性。这些构件均挂在原 `BLDG__*` 根节点下，不改变建筑选择和楼层爆炸交互。

关键工业建筑新增运营维护细节：屋顶设置防滑检修步道、双横杆安全护栏、组合式 HVAC 机组、风管和外墙检修梯；建筑正立面设置消防箱、配电柜、警示牌和公用工程管线入口。原料仓库与成品仓库分别布置独立托盘堆、装卸防撞柱、叉车和装卸人员。叉车通过 GLB `yard-shuttle` 元数据沿仓库装卸面声明的局部轴往返，Web 端会保持其停留与返程朝向，并在暂停交通或减少动态效果时恢复安全停放位。全部新增构件继续挂在对应 `BLDG__*` 根节点下，可随建筑聚焦、隐藏和分层检查同步管理。

建筑美术第一阶段建立了按功能分级的 PBR 材质体系：主生产建筑使用冷灰涂层金属，仓储建筑采用偏暖的物流灰，工艺车间使用蓝灰面板，公用工程建筑使用更深的金属灰，实验及门岗建筑保持洁净中性，综合管理中心则使用浅暖石材。每栋建筑通过 `artDirection` GLB 元数据记录其视觉身份，墙壳与四面墙板共同使用对应材质族。Web 日间模式同步采用中性蓝灰环境光、暖色主光和更克制的曝光，以保留墙板色差、阴缝与檐口体积；傍晚模式继续使用暖色运行照明和较低环境曝光。

建筑围护现已从主视角双面深化为完整四面建模。每栋建筑的正面、背面、左侧和右侧都具有独立保温墙板、物理阴缝、上下压条、耐久裙墙、水平标高带与四角金属收边；背面补充检修门、雨棚、天沟和成对落水管，工业建筑右侧增加设备百叶，办公及管理建筑右侧增加服务窗。墙板与石材采用偏白的冷灰、暖灰和米白色阶，并通过中间面板、深色物理阴缝和金属收边保留构造对比，避免自由旋转后出现没有层次的纯白墙壳。GLB 使用单段实体倒角保留边缘高光，并以 40 MiB 作为包含嵌入式 PBR 贴图后的正式 Web 资产预算。

室外场景包含环厂道路、内部车道、通往全部建筑的接入支路、门前硬化区、路缘石、排水沟、斑马线、方向标线、消防栓、停车位与挡轮器、门卫闸机和动态车辆。原料配送车、设备维保车和消防巡逻车使用 Blender 写入 GLB 的路线与路径点，Web 端按真实路段长度采样并处理到站停留、返程或循环；车辆位置始终位于经过碰撞审计的道路折线上，车头航向通过前后物理距离窗口在路口渐进转向。绿化采用工业园区的秩序型设计，包括外围树列、内部乔木、树池、雨水花园、灌木和观赏草；闸门车辆通道、建筑支路及入口视线范围设有无树净空区。

建筑美术第二阶段重点深化综合管理中心：采用独立的半透明蓝灰玻璃与铜色金属框架，中央玻璃幕墙向外形成真实夹层，后方布置暖色大厅背景、接待台、休息沙发和绿植。石材翼墙增加大板分缝，入口雨棚增加深色金属吊顶与三条暖色线性灯，使日景下也能读出玻璃、框架、石材和大厅的前后关系。全部新增对象仍归属 `BLDG__administration`，因此整栋选择、全层爆炸、内部聚焦和园区单体模式保持兼容。

建筑美术第三阶段补充工业园夜景与导视体系。每栋建筑配置成对暖色入口灯和带编码条的琥珀身份牌，主生产车间、原料仓库、成品仓库及东区工艺车间增加冷色作业灯；管理中心大厅背景与门廊线性灯统一标记为暖色大厅照明。灯具通过 GLB `lightRole` 元数据声明 `entry-warm`、`task-cool`、`wayfinding-amber` 或 `lobby-warm` 角色，Web 端在日间保持克制亮度，在傍晚按色温和用途分别增强。该方案只使用少量发光实体与共享材质，不导出大量实时点光源，兼顾大屏远中景辨识度和渲染性能。

场地美术第四阶段在 Blender 中完善地面、道路与景观的写实层次。环厂道路和主要内部道路增加低对比沥青修补、方向性车辙、伸缩缝与铸铁检修盖，入口广场补充连续铺装分缝，停车棚下增加十个带编号元数据的车位标识；雨水花园和花境则使用暖色骨料边带、覆盖物基底与三档乔木色调建立地表深度。新增对象统一归入 `SITE__surface-art`，通过 `layerRole` 保留语义，并避开建筑、球场和闸门净空。上述几何和基础材质随 GLB 导出，Web 端仍只负责光影、色调和交互，不依赖运行时外部贴图。

中近景美术第五阶段补充园区生活与运营叙事。篮球场和网球场采用低透明围网背板与实体横纵线材组合，兼顾 GLB 透明渲染稳定性和近景镂空感，原有可开合人行门继续保留；管理中心、实验区及运动区周边增加木质座椅、分类垃圾桶和步行导视柱，绿化边缘增加十二组低层灌木。门岗增设车牌识别摄像设备和安全锥，两个仓库装卸区增加周转笼与作业锥，园区步道增加三名带巡逻动画元数据的人员。除随球场根节点移动的围网线材外，新增街具与运营道具统一归入 `SITE__operational-story`，并通过模型合同保持建筑、球场和车辆路线净空。

材质与光影第六阶段建立建筑表面使用痕迹和接地阴影策略。Blender 为每栋建筑输出独立 `SURFACE_DETAIL__<building-id>` 根节点，包含四面低位耐候色差、少量雨痕和两组屋面色差片；综合管理中心使用更浅、更少的痕迹，工业及仓储建筑保留相对明显但克制的维护质感。所有表面细节以 `detailTier=micro` 标记并随所属 `BLDG__*` 节点移动。Web 端将主光阴影视锥扩大到完整园区范围，建筑实体投射并接收柔和阴影，场地网格接收阴影，而透明围网、玻璃和微细节不参与投射，减少黑块、闪烁和无效阴影开销。

地面与植被 PBR 阶段为沥青、混凝土、入口铺装、草地、雨水花园土壤、种植覆盖物和外围林地生成可平铺的 Base Color、Normal、Roughness 小尺寸贴图，并直接打包进 Blender/GLB，不依赖 Web 端额外纹理请求。树木改为锥形收分树干和多团簇树冠，外围林带采用靠厂区疏矮、向外渐密渐高的三段式树群，配合椭圆草甸和低矮灌木消解规则绿板边界；园区及背景林带继续按少量原型链接复用。Web 日间模式使用更明亮的广域环境光和克制的直射光，使地面、植被及背光立面可读，同时保留浅色屋顶的高光空间。该阶段使用 40 MiB GLB 部署预算，为嵌入式 PBR 保留空间。

地面接触写实阶段在不改变厂区布局的基础上，把场地细分为新铺沥青、老化沥青、装卸混凝土、入口铺装、停车面、人行步道、草坪、覆盖物与裸土九种功能材质，并以接近真实尺寸的 UV 平铺尺度保持远景秩序和近景颗粒。车辆转弯与装卸区域增加克制的轮胎暗痕和油迹，硬化地坪增加施工缝、修补和排水变色，月台及墙脚增加磨耗与积尘，树池以实体覆盖物完成地面过渡；所有痕迹均绑定既有路线、排水、月台或建筑锚点，并避开球场与闸门净空。增量维护入口为 `tools/blender/update_factory_ground_contact.py`，可独立更新正式 `.blend` 与 Web GLB。

植被写实深化阶段在保持全部树木位置和净空不变的前提下，将重复团状树冠升级为阔冠、开展、柱形、景观、林地和针叶六种可复用轮廓，并以 `vegetationSpecies`、`vegetationTier` 元数据区分近、中、远三档。近景庭院树使用深叶、中叶和受光叶三层标准 PBR 材质；八个独立非焊接叶团通过降低团块体积、拉开轮廓间距形成可见孔隙，树干向上延伸为四组一级主枝和八组二级枝杈，使近景不再呈现实心绿球。所有叶材保持双面、不透明标准 PBR，不使用易排序出错的混合透明。中远景树继续链接共享网格，以旋转、非等比缩放、色层与林带高度变化避免复制感。

树基与林缘生态层统一归入 `SITE__vegetation-ecology`。十二株近景庭院树在原树池下增加薄层裸土过渡，并以少量疏草连接树池和草坪；背景林地在球场围网之外增加不规则落叶斑和低层灌木带，全部对象通过 `anchorName` 锚定已有树干或林地，不进入篮球场、网球场和闸门净空。树皮及主要叶色继续内嵌 Base Color、Normal、Roughness 贴图，GLB 不依赖 Blender 专属程序节点或外部纹理请求。增量维护可通过 `tools/blender/update_factory_vegetation_realism.py` 更新现有 `.blend` 并重新导出 Web GLB，无需重建已经确认的建筑、道路和交互层级。

工业运营叙事阶段将新增内容统一归入 `SITE__operational-realism`，并按装卸、工艺、管理入口和门岗等命名作业区集中布置。两处仓库增加硬化装卸坪、月台防撞块与门封、托盘、周转笼、安全锥和服务标识；工艺区增加阀门、现场仪表、边缘桥架与贴附管线的识别标签；管理入口使用座椅、金属花钵和克制的身份导视强化到达感。全部可见构件通过 `operationRole`、`operationalZone`、`anchorName` 和 `layerRole` 元数据声明职责，并通过模型合同保持球场、闸门和车辆轨迹净空。六名作业人员采用 `task-route` 短路线，在装卸检查、仪表巡检、门岗核验及访客接待点停留后返回，不再进行无目的随机游走；Web 端根据 `dwellFraction` 区分步行、检查、返程和汇报阶段，交通暂停或减少动态效果时恢复静止安全位。增量维护入口为 `tools/blender/update_factory_operational_realism.py`。

Web 写实渲染阶段在 Three.js 中统一处理 GLB 标准 PBR 材质。颜色贴图固定为 sRGB，Normal、Roughness、Metalness 与 AO 使用非色彩空间；墙面、地面等斜视纹理最高使用 8× 各向异性。日间 PBR 环境反射默认值为 `0.10`，仍可在高级光照控制台调节；玻璃与金属使用独立较高档，室内家具和设备使用较低反射及更强接触分离，避免近景出现塑料白。PMREM 仅作为场景环境反射，不替换蓝灰天空，并随日间、傍晚模式分别调整强度与旋转方向。

画布渲染链使用 ACES Filmic、sRGB 输出、PCF Soft Shadow、轻量 SSAO 接触层、SMAA 边缘稳定和高阈值选择性 Bloom。Bloom 阈值设为 `2.2`，只允许高强度运营灯和少量玻璃高光产生辉光，不捕获白墙、道路标线或画布外的驾驶舱文字。相机距离在 `88` 单位内使用高质量构造和 8× 纹理过滤，`88–120` 单位关闭微细节并降为 4×，更远距离或减少动态效果模式进入确定性性能档并关闭枝杈细节与后处理。当前 GLB 低于 40 MiB 且所有 PBR 图片已内嵌，因此没有启用 KTX2；只有完成墙面和植被逐帧对比且无可见损失后才考虑压缩。

建筑 PBR 写实阶段在 Blender 中建立五套可维护材质族：工业厂房采用 `industrial-coated-metal` 涂层金属墙面，仓库采用 `warehouse-sandwich-panel` 夹芯板，综合管理中心采用 `administration-limestone` 石材，勒脚、路缘与人行面采用 `architectural-concrete` 混凝土，屋面及金属收边采用 `galvanized-roof` 浅色涂层镀锌板。每套材质都导出内嵌 Base Color、Normal、Roughness 与 Occlusion 通道；同族构件共享数据贴图，同时按构件保留原有底色变化，从而兼顾近景材质辨识度和 GLB 体积。四面墙壳和墙板变体统一提升到偏白的冷白、暖白及浅米白范围，中间板不再使用容易在背光面发黑的深灰底色，深色对比仅保留在物理阴缝、窗框、设备与装卸构件。生成器会在写入像素前设置 Normal、Roughness 和 Occlusion 图像的 `Non-Color` 色彩空间，避免 Blender 5.2 在切换色彩空间时把生成贴图清零；模型合同会重新导入正式 GLB 并验证 Normal 与 ORM 像素通道。墙面、石材、混凝土和涂层屋面均保持低金属度，屋面使用更高粗糙度与银白底色，避免在没有环境反射贴图的 Web 场景中呈现黑色金属反射；建筑 UV 按实际尺寸重复，避免大立面纹理拉伸。正式资产进一步加入硬性浅色合同：主要墙材贴图均值保持在 `0.80–0.93`、最低值不低于 `0.62`，墙面金属度不高于 `0.12`、粗糙度保持在 `0.58–0.84`；日间环境反射默认值为 `0.10`，并以六个环绕方位检查正面、侧面、背面和屋顶不发黑。Web 端不请求外部建筑纹理，仍由 Blender 文件作为材质维护与再导出的唯一来源。

厂区美术第一阶段重建 Web 日间光照与开场构图。日间环境由深海军蓝背景调整为明亮蓝灰建筑天空，降低远景雾密度并提升半球光的地面反射色；无阴影方向补光移至主光对侧，并增加一盏受日间/傍晚模式分别控制的中性立面环境光，使正面、侧面和背面的浅色 PBR 墙板都保持基础可读性，同时保留主光投射的柔和阴影。初始及复位镜头继续从参考图前左方向观察厂区，但距离由约 94 单位收近至约 80 单位并降低俯视比例，使综合管理中心、主生产车间和后排厂房形成更清晰的前中后景。傍晚模式及运营灯具参数保持独立，不受日间补光影响。

建筑构造深化阶段在不改变布局和浅色 PBR 色阶的前提下，为 12 栋可交互建筑补齐可测的构造层级。通用门窗采用四边回口、窄框、窗台和上部滴水，玻璃与门扇相对外侧构造面退进 `0.11` 模型单位；墙脚、四角金属收边、四边女儿墙、天沟及前后落水管均写入 `constructionRole` 元数据，并保持在对应 `BLDG__*` 根节点下。主要外露收边使用 `0.025–0.035` 的实体倒角，使白色立面依靠边缘高光和真实构造阴影产生层次，而不是通过压暗墙材制造对比。增量维护入口为 `tools/blender/update_factory_construction_depth.py`；更新器直接创建 Mesh 数据，避免 Blender 在大型场景中逐个调用操作符导致依赖图重复重建。

镜头闪线修复阶段移除了旧 `DETAIL__facade-joint-*` 系统，只保留四面模块化围护自身的实体阴缝，避免两套薄几何相互穿插造成 Z-fighting。后续抗摩尔纹阶段又将工业涂层墙面和仓库夹芯板的 Normal 强度收敛到 `0.08–0.09`，石材、混凝土和镀锌屋面限制为 `0.10–0.11`；建筑贴图的物理重复尺度扩大到 `3.2–5.0` 模型单位，高度场改为宽缓的低频变化，并降低 Base Color 的微小色差。近景层次继续由实体阴缝和压筋承担，驾驶舱中远景则通过低频贴图与 Web 三线性 mipmap 采样减少镜头移动时的摩尔纹。Web 默认以傍晚照明启动，页眉与场景按钮共享同一照明状态；OrbitControls 保留手动拖拽和阻尼，但不再在用户停止操作后自动旋转。增量维护入口为 `tools/blender/update_factory_architectural_pbr.py`。

道路深度与抗锯齿稳定阶段将相交的横向主路和纵向接入道路拆分为相差 `0.02` 模型单位的施工层，标线同步贴合各自路面，避免交叉口共面顶面争夺深度缓冲。增量维护入口为 `tools/blender/update_factory_road_depth.py`，可直接更新正式 `.blend` 并重新导出 GLB，无需重建全部 PBR 纹理。WebGL2 环境继续使用 SMAA；WebGL1 环境启用 FXAA，低像素密度画布使用 `1.2×` 渲染倍率，专注厂区视图提升到 `1.35×`，WebGL2 专注视图使用 `1.25×`。主光阴影贴图提升到 `4096²` 并收敛 bias，使屋顶、围栏与管线在镜头移动时更稳定。

厂区真实感收敛阶段依次补齐三个可移除系统。`SITE__ground-circulation-realism` 为五个主要生产和仓储建筑增加低频硬化服务场、施工缝与排水边界，并复用既有行车磨损表达清晰的车辆路径；维护入口仍为 `tools/blender/update_factory_ground_contact.py`。`VEGETATION__transition-realism` 对 271 个共享网格树冠施加确定性的高宽和位置变化，并把外围组织成乔木、灌木和草甸三层过渡；维护入口为 `tools/blender/update_factory_vegetation_realism.py`。每栋 `BLDG__*` 下新增独立 `SERVICE_ENVELOPE__*`，包含后场硬化面、银白检修门、百叶通风、雨棚、防撞柱和屋面维护标识，维护入口为 `tools/blender/update_factory_service_envelopes.py`。三套系统均导出职责元数据，正式 GLB 继续执行 40 MiB 上限。

Web 日间呈现使用 `1.34` 曝光和 `1.38` 半球环境填充，在保持日间 PBR 环境反射 `0.10` 的前提下抬升深色地面，不改动浅色建筑底色。专注厂区模式使用独立的近距低目标镜头预设，使扩大的厂区在全高视口内占据更完整的画面；退出专注或点击复位时会平滑返回对应模式的默认构图。

厂区光照控制在日间/傍晚模式按钮上方增加 `0–100%` 阳光强度仪表。日间默认 `78%`、傍晚默认 `42%`，两种模式分别记忆操作值；拖动滑杆会实时调整太阳主光、半球环境光、立面补光、环境反射与曝光，运营灯具仍由日间/傍晚角色独立控制，不会被阳光滑杆错误熄灭或放大。控件支持方向键、Home/End 和屏幕阅读器百分比反馈，并在首页、能源二级页面与专注厂区视图共用同一紧凑布局。

阳光仪表右侧的“调”按钮打开非模态高级光照控制台，按日光、环境、天空氛围和厂区灯具四组管理 26 项安全参数。可实时调整太阳主光、太阳高度与方位、主光/补光颜色、阴影柔和度、曝光、半球光与地面反射色、立面补光、PBR 环境反射及旋转、天空与雾颜色、雾密度、Bloom、道路灯、强调灯和各角色建筑灯具。所有数值均由 schema 限制在不会破坏浅色建筑可读性和后处理稳定性的范围内；日间与傍晚配置独立记忆，“恢复当前模式”只重置正在编辑的模式，“全部恢复”同时恢复两套配置及 `78% / 42%` 阳光默认值。面板默认收起，支持页签键盘焦点、颜色选择器、范围滑杆、关闭按钮和 Escape 关闭，并在首页、能源二级页面及专注厂区视图保持同一实时状态。

选中建筑后可从楼层剖面打开“材质实验室”，在不修改 Blender 源文件或 GLB 几何的情况下预览现有五套内嵌 PBR 材质族：涂层金属板、仓库夹芯板、浅色石灰石、建筑混凝土和镀锌屋面板。墙面、屋面与勒脚使用各自符合构造逻辑的候选材质；每次编辑都会为当前建筑克隆独立的 Base Color、Normal、Roughness 与 AO 纹理，因此不会影响其他建筑或共享模板。操作员可在安全范围内调整色调、粗糙度、法线强度、AO、纹理缩放和单体环境反射，并通过“恢复当前构件原材质”精确还原 GLB 初始材质引用。材质修改仅保留在当前 Web 会话，不增加运行时纹理请求，也不改变正式 GLB 体积。

生产工艺设备阶段在保持厂区布局不变的前提下，为主生产车间一层增加两套装配机械臂工作站，为前区原料仓库一层增加一码垛机械臂工作站。每套工作站包含分层关节、输送辊道、工件、控制范围、安全围栏和警示灯；中央处理车间与东区工艺车间的一、二层增加局部设备管道、阀门和支架。点击建筑并进入楼层爆炸/内部聚焦视角后可近距离观察。这里的管道属于固定的生产工艺设备，不是水网、电网、蒸汽网或气网可视化，也不会显示发光流向。Blender 负责机械臂与设备实体及关节元数据，Web 端 `robotArmAnimation` 负责转台、肩、肘、腕、夹爪和工件的循环动作；启用“减少动态效果”时恢复 Blender 原始姿态。

主要资产：

- `assets/blender/factory-campus-graybox.blend`：可编辑 Blender 源文件
- `public/models/factory-campus-graybox.glb`：Web 端加载的模型
- `tools/blender/create_factory_campus_graybox.py`：确定性模型生成脚本

生成脚本是模型结构的维护入口。需要修改建筑、道路或绿化时，应先更新生成脚本及场景合同测试，再重新生成 `.blend` 和 `.glb`，避免手工编辑结果在下一次导出时丢失。

在 macOS 上重新生成模型：

```bash
/Applications/Blender.app/Contents/MacOS/Blender \
  --background \
  --python tools/blender/create_factory_campus_graybox.py \
  -- \
  --blend-output assets/blender/factory-campus-graybox.blend \
  --glb-output public/models/factory-campus-graybox.glb
```

GLB 中的可交互节点遵循以下命名规则：

- 建筑：`BLDG__<building-id>`
- 楼层：`FLOOR__<building-id>__<floor-id>`
- 室内功能区：`ZONE__<building-id>__<floor-id>__<zone-id>`
- 立面构件：`FACADE__<building-id>__*`
- 屋面收边与排水：`ROOF__<building-id>__*`、`SERVICE__<building-id>__*`
- 闸门识别与交通设施：`GATE__recognition-zone`、`GATE__stop-line`、`GATE__speed-bump-*`、`GATE__lane-arrow-*`
- 动态闸门车辆：`VEHICLE__gate-shuttle__root`
- 运营路线：`ROUTE__<route-id>`
- 路径点：`WAYPOINT__<route-id>__<order>`
- 路线车辆：`VEHICLE__delivery-truck__root`、`VEHICLE__maintenance-van__root`、`VEHICLE__fire-patrol__root`
- 作业叙事根节点：`SITE__operational-realism`
- 任务人员与锚点：`TASK_OPERATOR__*`、`TASK_ANCHOR__*__start`、`TASK_ANCHOR__*__end`
- 机械臂工作站：`ROBOT_CELL__<building-id>__<floor-id>__<cell-id>`
- 局部工艺管道：`LOCAL_PROCESS_PIPE__<building-id>__<floor-id>`

楼层爆炸动画、三面剖切房间、内部检查灯光、聚焦镜头和路线车辆位移由 Web 端 Three.js 控制；Blender 负责提供可独立移动的楼层节点、功能区、内部物体、路线节点、路径点和车辆动画元数据。`campusRouteRegistry` 将 GLB 路径点整理为不可变路线，`campusRouteAnimation` 负责等距采样、停留周期、人员任务阶段和转角航向平滑；仓库叉车使用轻量 `yard-shuttle` 按轴往返，任务人员则使用带检查与汇报停留的 `task-route`。闸杆与门口车辆继续共同消费独立的 `gateTrafficCycle` 状态机，确保车辆进入识别区后停车、闸杆向上抬起再放行，并在车辆清场后向下落回水平关闭位。交通演示按钮暂停路线车辆和仓库叉车；启用“减少动态效果”时，人员/车辆停止，闸杆恢复关闭。

GLB 预算上限为 40 MiB（41,943,040 字节）。预算覆盖地面、植被和五套建筑材质的嵌入式共享 PBR 贴图及可复用植被网格；树木继续通过链接网格与对象尺度变化控制体积，不得为此模型增加运行时外部纹理请求。

## 测试

Web 功能与场景合同：

```bash
npm test
```

Blender 模型合同测试建议单并发运行，避免同时启动多个 Blender 进程：

```bash
node --test --test-concurrency=1 tools/blender/create_factory_campus_graybox.test.js
```

测试覆盖建筑节点、楼层元数据、内部设施、建筑间距、墙面构造、道路与停车设施、绿化层次、闸门入口净空、运营路线与路径点、车辆动画、相机方向和 GLB 加载回退。

完整交付检查：

```bash
npm test
node --test --test-concurrency=1 tools/blender/create_factory_campus_graybox.test.js
npm run build
test $(stat -f%z public/models/factory-campus-graybox.glb) -le 41943040
git diff --check
```

Blender 合同测试在同一进程中复用一次完整生成结果，随后分别检查 GLB 节点、布局、PBR 材质、构造立面、室内层级和绿化指标，避免重复启动多个 Blender 实例。
